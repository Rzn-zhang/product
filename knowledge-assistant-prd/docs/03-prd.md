# PRD：工业设备售前知识库助手

版本0.1，设计状态，2026-10-05。关联需求分析、验收用例和评测计划。原型是交互样例，不是以下全部能力的实现。

## 1. 目标与非目标

目标：让售前在准备答复时，找到适用且有权限的资料，核对出处，知道哪些内容需要技术审核。

首期支持内部问答、引用、有效文档管理、问题反馈与人工接管。非目标：自动发给客户、自动报价、控制设备、替代技术承诺、连接真实客户系统。对实际设备的操作与安全问题一律交由专业人员确认。

## 2. 权限矩阵

| 操作 | 售前 | 资料维护人 | 技术审核人 | 管理员 |
| --- | --- | --- | --- | --- |
| 检索/查看引用 | 授权范围内 | 授权范围内 | 授权范围内 | 授权范围内 |
| 上传/解析/发布 | 否 | 是 | 否 | 配置授权，不默认读所有内容 |
| 修改文档ACL | 否 | 仅被授权范围 | 否 | 是，记录审计 |
| 提交反馈/工单 | 是 | 是 | 是 | 是 |
| 审核工单 | 否 | 否 | 被指派范围 | 配置指派策略 |

角色不替代文档范围。客户端不能自行传入可信用户或角色；服务端从登录会话得到身份。检索、引用打开、导出、缓存命中和历史会话均重新检查ACL。不可读文件不暴露标题、片段或是否存在。

## 3. 主流程与信息架构

问答工作台：型号/版本 → 提问 → 检索/回答状态 → 引用 → 反馈/人工接管。

文档管理：上传 → 解析 → 元数据补全 → 预览 → 发布 → 失效/替换。

问题记录：问题与会话快照 → 分类 → 负责人 → 处理结论 → 复测。首期不把未审核回答自动加入知识库。

## 4. 功能规则

### F01 文件导入与生命周期

计划支持TXT、MD、可提取文本的PDF与DOCX，单文件设计上限20MB。OCR、扫描PDF和复杂表格单列后续范围。服务端校验实际类型、大小、恶意文件与解析结果，不能只信扩展名。

文档元数据：doc_id、标题、型号、版本、生效日期、负责人、访问组、内容校验值、状态。缺少型号/版本/负责人/访问组时允许存草稿，不允许发布。

状态：uploaded → parsing → draft → published → withdrawn；解析可进入failed，重试创建新任务而不生成重复发布文档。相同校验值提示重复，显式选择保留或取消。发布完成后才进入检索索引。

新版本不默认覆盖所有型号。按型号、资料类型、生效日期定义有效版本；冲突待维护人确认。撤销后问答、引用、历史和缓存都不可再读该内容，未完成请求须复核。

### F02 提问、补问与生成

问题长度1-1000字符，空白禁止提交。普通参数问答缺型号/版本时先补问。界面提问字段不是唯一入口，后端同样校验。

流程：鉴权 → 适用文档过滤 → 检索 → 证据检查 → 生成草稿 → 关键参数与引用检查 → 返回。生成器输入只有可读的文档片段。资料中的“忽略规则”“执行命令”仅视为不可信文本。

状态：clarification、retrieving、generating、answered、insufficient_evidence、conflict、timeout、error。禁止把检索相似度当成回答置信概率展示。

无证据时说明无法从当前可用资料确认，不依赖模型常识补参数；可调整型号或转人工。当前资料同一参数矛盾时指出冲突并暂停结论，不擅自挑较新文件；高风险问题直接接管。

### F03 回答与引用

显示草稿标记、选用型号与版本、核心答复、适用条件、逐项引用。每条关键参数必须映射至少一条授权来源；未匹配的参数不进入正常答复。

引用结构：citation_id、doc_id、文档版本、section、片段定位、支持的claim_id。引用按钮由服务端鉴权后返回原文；访问撤销显示“来源不可用，请重新核验”，不能保留旧片段。页面标明正式回复需人工核验。

### F04 反馈与人工接管

反馈分类：正确有用、内容错误、引用不匹配、资料过期、缺少答案。后四类可补充说明。重复提交通过request_id+反馈用户+类型幂等处理，取消/修改保留审计。

工单包含型号、版本、问题、可授权引用、失败分类、描述与会话ID。提交前给用户核对；不默认复制客户姓名、报价和机密资料。工单idempotency_key防重复，成功后显示ticket_id与负责人，失败保持输入可重试。

### F05 运维与异常

15秒未完成显示超时，取消下游任务，不继续输出迟到回答；重试产生新request_id并关联原会话。上传失败不显示成功状态。额度/依赖异常使用明确错误码，回退人工查资料，不静默换到未经批准的外部模型。

请求取消、网络中断和重复点击需防重。权限中途变化以最新ACL为准，不能以“已经检索到了”为理由继续输出。

## 5. 示例接口契约（设计，尚未实现）

`POST /questions` 输入query、product_model、firmware_version、conversation_id、idempotency_key；身份来自会话，不接受客户端user_role。返回request_id、status、answer、claims、citations、error_code。状态为answered时answer与citations必须同时存在。

`GET /citations/{id}` 每次鉴权，返回可读片段与定位；不可读统一403，不泄漏文件名。

`POST /documents` 校验文件并返回doc_id/job_id；`POST /documents/{id}/publish` 校验元数据/ACL/状态；`POST /feedback` 写入分类；`POST /tickets` 返回ticket_id。

错误码：NEED_SCOPE、NO_EVIDENCE、VERSION_CONFLICT、FORBIDDEN、PARSE_FAILED、TIMEOUT、DEPENDENCY_UNAVAILABLE。字段及枚举需与前后端、技术负责人共同确认。

## 6. 事件与隐私

事件：question_submitted、clarification_shown、answer_completed、refusal_shown、citation_opened、feedback_submitted、ticket_created。记录request_id、状态、延迟、版本与脱敏用户标识；事件日志默认不保存原始问题、答案和客户信息。

排障内容单独受控、限定访问和留存期限。案例拟定日志保留30天、可删除的会话记录7天，均为待企业政策确认的建议。管理员访问也需留痕。

## 7. 交付与依赖

P0依赖可信身份、资料ACL、生效版本制度、可访问引用、人工审核人。任何一项缺失，不作为生产问答上线。

工作包：资料治理与标注 → 搜索基线 → 检索与生成PoC → 接口/交互 → 安全测试 → 内部试点。本文不承诺确定工期，须先确认文档规模、部署环境与团队能力。

## 8. 原型与PRD差异

原型实际支持情境切换、固定回答、来源抽屉、反馈登记、模拟工单、TXT/MD预览及解析失败重试。没有后端、安全鉴权、真实文件索引、模型请求或跨会话持久化。不可据原型通过称生产验收通过。
