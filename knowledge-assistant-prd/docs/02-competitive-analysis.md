# 公开资料对照与产品决策

查阅日期：2026-10-05。仅基于官方文档，没有购买、部署或做横向性能实测。没有依据的功能不标成“不支持”。不同版本与部署方式应另行确认。

## 1. 可核验能力

| 观察维度 | Dify | FastGPT | 对本方案的启发 |
| --- | --- | --- | --- |
| 检索与生成 | 检索节点将文档片段输出给下游模型 [S1] | 入门案例覆盖知识库与对话流程 [S2] | 明确拆开“检索不到”和“生成答错” |
| 引用 | 文档说明Chatflow可展示来源引用 [S1] | 入门案例包含引用原文 [S2] | 答复必须能回到具体资料 |
| 检索控制 | Top K、阈值、重排和元数据过滤 [S1] | 本次不比较参数调优能力 | 型号与版本应纳入过滤与评测 |
| 文件权限 | 本次文档不足以判断细粒度鉴权 | 商业版文件级权限，需知识库读权限；成员身份影响召回过滤 [S3] | 不能把有过滤器等同于安全鉴权 |
| 完整上线成本 | 未测试，不能据此定价或估工期 | 未测试，版本和授权条件待确认 | 先做有边界的PoC，不承诺一键落地 |

## 2. 不从功能数量决定选型

本方案优先解决参数溯源和人工审核，不自建通用Agent平台。可先评估现成平台是否满足：身份传递到检索节点、引用鉴权、有效版本过滤、错误码与日志、企业数据边界。

如果平台满足这些要求，可复用平台并开发业务界面；若不满足，应明确缺口与成本，不以“开源所以免费”作为结论。元数据过滤用于限制候选文档，生产权限仍须可信身份和后端校验。

## 3. 候选方案决策表

| 方案 | 优点 | 代价/风险 | 首期决策 |
| --- | --- | --- | --- |
| 搜索+人工摘录 | 易核验、实现简单 | 跨资料整理仍靠人 | 作为对照基线 |
| RAG+引用+人工审核 | 能组织答复且保留来源 | 需要标注、权限、版本治理 | 进入PoC候选 |
| 长上下文整本输入 | 小资料集可简化链路 | 上下文成本与权限仍需处理 | 少量文件任务单独验证 |
| 微调领域模型 | 可调整风格与固定任务表现 | 更新与溯源问题仍存在 | 本期不选 |
| 自主Agent自动报价 | 可能减少流程操作 | 商业承诺、工具调用风险高 | 明确排除 |
