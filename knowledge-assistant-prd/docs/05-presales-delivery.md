# 售前演示与交付检查

本页是自主设计的方案模板，不代表已对接客户、投标、签单或完成部署。

## 1. 首次沟通要确认什么

业务：谁答复、每天问题量、错误成本、当前搜索工具、审批流程；资料：格式、规模、更新制度、能否标注适用型号；安全：能否外发、账号体系、资料范围、留存要求；落地：环境、责任人、审核资源、验收人。

先要求提供获准使用的脱敏样例，不索要完整客户文件。输出双方确认的问题清单、非目标、PoC范围和验收口径，再谈实施方案。

## 2. 5分钟演示脚本

1. 30秒：说明模拟工业网关场景，核心任务是核对参数，不是替代工程师。
2. 60秒：选择“参数问答”，打开引用确认型号、版本和适用条件；强调数字为虚构演示资料。
3. 60秒：选择“缺少型号”和“无依据”，说明补问与拒答为什么优于猜测。
4. 60秒：展示“版本冲突”，转人工并查看工单所需上下文。
5. 60秒：文档导入/解析失败重试，说明未发布资料不进入答案。
6. 30秒：强调原型没有真实模型和权限后台；建议下一阶段用授权资料验证。

## 3. 常见追问

“准确率多少？” 当前无实测。先共同定义可答任务、正确参数、有效引用和不可答任务，再用盲测集验证。

“本地一定便宜吗？” 不一定。需要硬件、并发、运维、模型效果和人工审核成本；应分别比较本地与获准外部服务的总成本。

“和现成平台有什么不同？” 本案例不是替代平台，主要提出售前参数核验、版本冲突和人工审核的业务要求，可评估在现成平台实现。

“能自动报价吗？” 首期不能。报价涉及商业权限、价格有效性和对外承诺，需要另立项目和审批规则。

## 4. PoC与交付边界

| 工作包 | 需提供的条件 | 交付证据 | 不包含 |
| --- | --- | --- | --- |
| 资料整理 | 授权资料与维护人 | 元数据表、版本清单 | 未授权客户资料采集 |
| 环境验证 | 网络、资源和安全审批 | 环境报告、失败项 | 未验证的并发承诺 |
| 问答PoC | 模型边界与标注集 | 评测明细、引用核验 | 自动对客发送 |
| 权限与日志 | 身份源、ACL、留存制度 | 越权负向测试、审计记录 | 只用前端模拟当鉴权 |
| 上线交接 | 负责人、回退方案 | 操作手册、回滚演练 | 无人维护的“交付即结束” |

## 5. 部署与排查清单

部署前：批准环境、模型/嵌入兼容、索引版本、资源容量、身份映射、密钥存储、备份、数据留存、监控阈值。依赖版本固定，不能把密钥提交GitHub。

排查：索引为空先查解析任务；检索为空查型号/版本与ACL过滤；引用错误查片段定位与文档快照；依赖失败查连接和凭据，不把秘钥写日志；超时按链路阶段定位。排查后记录影响范围、修复与回归证据。

交接：环境配置（无密钥）、发布/撤销手册、错误码表、人工审核分工、监控、备份恢复、回退演练、未解决风险。未完成安全验收不进入生产。

## 6. ROI表如何算

月净收益 = 合格任务量 × 每任务审核后节省分钟 / 60 × 完全人力小时成本 − 模型/检索/基础设施/维护增量成本 − 预计错误损失。

应由企业提供基线，分别算保守/中性/乐观情境；审核时间、重试和培训成本都计入。本案例没有真实输入，不填“节省15%”或“年收益XX万元”。时间减少也不必然意味着可削减对应人数。
