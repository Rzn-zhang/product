# 面试讲解与个人复核

## 1. 三分钟结构

这是基于已有课程知识库问答经历延伸的自主产品设计案例，面向工业设备企业内部售前。案例没有实际客户、线上指标和生产部署。

我选择的产品问题不是“怎么增加聊天功能”，而是售前答复里如何核对型号、版本和参数来源。因此范围收敛为授权资料问答、引用核验、缺信息补问、冲突接管和文档发布。自动报价和设备控制不在首期。

方案将检索、生成与审核分开，关键参数需要引用，资料没有答案就拒答，版本冲突不替用户猜。权限在后端检索前限制，引用、历史和导出也要复核，不能只隐藏按钮。

交付包括需求假设、官方文档对照、PRD、20条设计验收用例、试点评测计划和可点击原型。原型是固定样例交互，不是已经实现的企业RAG产品。下一步要访谈用户、取得脱敏资料并完成搜索基线和盲测。

## 2. 必须自己能回答的取舍

| 问题 | 需要讲清楚的判断 |
| --- | --- |
| 为什么不做Agent？ | 当前任务是有依据的答复，不需要自主动作，避免扩大权限 |
| 为什么留人工审核？ | 参数可能成为技术承诺，原型不具备生产质量证据 |
| 为什么先问型号？ | 同一接口名称可能在不同版本有不同限制 |
| 只看引用点击率行吗？ | 点击不代表答案正确，还要审核正确性和版本适用 |
| 指标门槛怎么定的？ | 当前是初拟目标，要根据风险、基线与实测修订 |
| 你亲自做了哪些？ | 只描述自己确实阅读、修改、演示或验证过的部分 |

## 3. 使用简历前的清单

先打开原型演示五个分支；阅读PRD权限规则；选三条验收用例解释为什么重要；按自己的判断修改至少一项范围或验收标准。没有实际完成就不要把准备文档说成独立设计或真实上线经验。

完成个人复核后可参考以下项目描述，不将设计计划写成执行结果：

工业设备售前知识库助手产品设计案例：围绕参数核验与资料溯源场景，梳理问答、引用、版本管理与人工接管流程；形成PRD、验收用例及售前演示方案，以可点击原型呈现正常问答和异常处理路径。

这里的“形成”仅描述作品产物，个人承担的工作应由本人确认。不要写客户认可、效率提升或生产交付。
