# VOC Lens 产品与评估说明

## 1. 问题定义

客服工单、应用评论和访谈记录散落在不同渠道。产品经理逐条阅读耗时，而且单纯统计正负面无法回答三个排期问题：问题集中在哪里、影响多大、为什么要优先处理。

目标用户是 AI 产品经理、产品运营和用户研究人员。核心任务是把原始反馈转成可核验的主题机会池，并保留代表性原文，方便回看证据。

## 2. 数据契约

最小输入只有文本列；日期、评分和渠道为可选字段。系统会清洗空文本、长度小于 4 的文本和完全重复文本。输出包含：情感标签、情感分、置信度、业务主题、关键词、机会分和代表性原文。

内置的 40 条反馈与 18 条情感标注均为演示数据，不代表真实用户或业务收益。

## 3. 核心流程与选择依据

`CSV -> 清洗去重 -> 词典情感 -> 字符/词元 TF-IDF -> 余弦 K-Means -> 业务主题合并 -> 机会分 -> 人工核验`

- 词典规则：优点是离线、低成本、每次结果一致，适合做产品原型的可解释基线；缺点是不能理解反讽、长距离否定和领域新词。
- 字符与二元片段：不依赖中文分词包，降低复现成本；代价是语义表达弱于向量模型。
- K-Means：适合快速发现重复话题，固定随机种子 42 保证演示可复现；聚类数仍需要结合样本规模调参。
- 业务主题合并：统计聚类可能把同一问题拆成多簇，因此再映射到性能、回答质量、知识库等产品主题，避免机会池重复。

## 4. 机会分口径

对每个主题计算：

`机会分 = 100 × (0.35 × 相对反馈量 + 0.45 × 负向率 + 0.20 × 严重度)`

- 相对反馈量 = 该主题反馈数 / 最大主题反馈数。
- 负向率 = 该主题负向反馈数 / 该主题反馈数。
- 严重度 = `1 - (平均评分 - 1) / 4`；没有评分时回退为负向率。
- 默认更重视负向率，因为高频但满意的问题不一定需要进入修复排期。权重是产品假设，不是统计真理，真实项目需要用业务损失和人工评审校准。

例：相对反馈量 0.8、负向率 0.6、严重度 0.7，则机会分为 `100 × (0.28 + 0.27 + 0.14) = 69`，进入 P0 候选，再由产品人员核验原文后决定是否排期。

## 5. 验收标准

- 输入含空行和重复反馈时，系统不崩溃并能报告去重数量。
- 中文否定句如“响应并不慢”“界面不是很好用”不能按关键词表面含义直接判断。
- 同一数据与参数重复运行，主题结果应稳定。
- 每个高优主题必须能回溯至少一条原始反馈，不能只展示聚合数字。
- 导出的结论必须注明样本范围、规则口径与方法边界。

## 6. 已知 Bad Case 与处理

1. “不是很好用”最初因命中“好用”被判为正向。修复方式是在情感词前检查否定作用域，并增加回归测试。
2. 反讽句“真是太快了，等了半小时”仍可能误判。真实上线需引入人工标注集和语义分类器。
3. 聚类会把同一业务问题拆成多个统计簇。当前先用主题词规则合并，长期方案是人工命名与向量聚类结合。
4. 评分与文本可能冲突。当前文本占 75%、评分占 25%，冲突样本进入人工复核而不是强行相信其中一个。

## 7. 真实上线还缺什么

至少需要 200-500 条真实且脱敏的人工标注反馈，报告各类别 Precision、Recall、F1；两名标注者独立判断主题并计算一致性；高优主题抽样复核“可行动洞察率”；持续记录 Bad Case 和词典版本。
