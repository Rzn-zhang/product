# 架构与产品决策

## 1. 用户与场景

目标用户是需要快速阅读大量反馈的产品经理、产品运营和客户成功团队。典型输入来自应用商店、客服工单、问卷和访谈，典型输出是需求池证据、版本复盘和专项问题清单。

## 2. 为什么不直接调用大模型

- 演示项目需要开箱即用，不能把可运行性绑定在个人 API Key 上。
- 用户反馈可能包含企业敏感信息，本地分析更容易说明隐私边界。
- 词典和无监督聚类虽然上限较低，但每个判断可追溯，适合先验证产品流程。
- 后续可把情感模块替换为分类模型，把主题模块替换为 Embedding 聚类，而不改变 API 和前端。

## 3. 数据链路

1. **清洗**：链接归一、空白压缩、短文本过滤、精确去重。
2. **情感**：双语词典计分，识别前置否定词和程度词；若有 1-5 星评分，则文本占 75%，评分占 25%。
3. **表示**：中文字符与二元片段、英文单词共同构建 TF-IDF 向量。
4. **聚类**：固定随机种子，使用余弦相似度迭代 K-Means。
5. **业务映射**：根据主题关键词映射到产品语言，并合并重复业务主题。
6. **排序**：机会分 = 反馈量权重 × 相对反馈量 + 负向权重 × 负向率 + 严重度权重 × 评分严重度。

## 4. 关键指标

- 模型指标：情感 F1、主题纯度、人工一致性、Bad Case 数量。
- 产品指标：可行动洞察率、分析耗时、需求证据覆盖率、人工复核耗时。
- 护栏指标：误判高风险反馈比例、敏感信息泄漏、重复主题率。

## 5. 下一步迭代

- 引入人工标注页面，沉淀领域训练集。
- 增加 Embedding 聚类与当前算法的 A/B 对比。
- 接入工单系统，支持增量分析和主题漂移监控。
- 生成包含问题、证据、影响范围、验收指标的需求卡片。
